## OIR answer/score hardening (security finding)
- `GET /api/content/oir` records a served set in `content_sets` (migration `20261101000400_rounds_content_sets.sql`, 60 min expiry) and returns `setId`.
- `POST /api/content/oir/check {setId, questionId, index}`: only for a question in the caller's own unexpired set, once per question (atomic SQL function `content_record_answer`); unknown/foreign sets 404, outside question 403, repeat 409, expired 410; rejected/inactive questions 404.
- The OIR result (`POST /api/evaluation/run`, OIR) takes only `{ setId }`; score and total come from the server-checked answers; any client score is ignored; one result per set (Firestore doc id = set id, repeat 409). Verified results only appear on the leaderboard.
- Legacy mobile (no setId): still accepted so the Flutter app is not broken, but the score is clamped, stored with `verified:false` and kept off the leaderboard. Set `OIR_REJECT_UNVERIFIED=true` to refuse them once the app is updated.
- NOT fixed (not my files, mobile depends on them): `GET /api/firestore/oir/questions` still returns `correct_answer_index` for the whole Firestore bank, and `POST /api/firestore/oir/results` saves whatever the client sends. The mobile app should move to `/api/content/oir` + the set flow, then those two endpoints should be removed or locked. Other banks (WAT, SRT, lecturette) return no answers or hidden rubric, so no binding was needed.
- Tests: `test/contentBank.test.js`, `test/oirResult.test.js` (unknown id, other user's set, repeat, expired, forged score).
